# API базы знаний

База знаний хранит исходный текст и чанки в SQL и, когда включён Qdrant,
индексирует чанки настроенной embedding-моделью.

## Документы

### `GET /api/v1/knowledge/documents`

Возвращает документы текущей компании из JWT `tenant_id`.

Ответ:

```json
[
  {
    "id": "uuid",
    "title": "FAQ Telegram",
    "source_type": "manual",
    "storage_url": null,
    "status": "ready",
    "version": 1,
    "chunks_count": 1,
    "created_at": "2026-06-29T12:00:00Z",
    "updated_at": "2026-06-29T12:00:00Z"
  }
]
```

### `POST /api/v1/knowledge/documents`

Создаёт ручной текстовый документ и сразу нарезает его на чанки в БД.

Тело:

```json
{
  "title": "FAQ Telegram",
  "source_type": "manual",
  "text": "Telegram подключается через токен бота.",
  "tags": { "topic": "telegram" }
}
```

`source_type` поддерживает `manual`, `txt`, `md`, `pdf`, `docx`, `xlsx`, `url`.

### `POST /api/v1/knowledge/documents/upload`

Принимает `multipart/form-data`:

- `file` — обязательный файл UTF-8 TXT/MD, PDF, DOCX или XLSX, максимум 10 MB;
- `title` — необязательное название (по умолчанию имя файла без расширения);
- `tags` — необязательный JSON-объект со строковыми ключами и значениями.

Текст извлекается в памяти, исходный файл не сохраняется. Для OOXML проверяются
размер распакованного архива и число элементов; для PDF ограничено число страниц;
для XLSX — число листов, строк и ячеек. После извлечения используется тот же путь
чанкинга и Qdrant-индексации, что и для ручного текста.

Сканированные PDF без текстового слоя отклоняются с понятной ошибкой: OCR и
загрузка PNG/JPG пока не поддерживаются.

## Кандидаты автообучения

### `GET /api/v1/knowledge/candidates`

Возвращает кандидатов текущей компании.

### `POST /api/v1/knowledge/candidates/{candidate_id}/approve`

Подтверждает кандидата, создаёт новый документ базы знаний и один чанк вида
`Вопрос → Ответ`. Повторный approve идемпотентно возвращает уже созданный документ.
